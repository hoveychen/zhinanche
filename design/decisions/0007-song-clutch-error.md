# 0007：宋史式离合的入齿误差进网页

- **状态：** 已采纳（song-clutch 子任务）。
- **日期：** 2026-10-21
- **接着：** [0006](0006-cad-level-chariot.md)（齿形、齿隙 48%）；[0001](0001-which-reconstruction.md)（默认差动式，宋史式可切换，「车夫帮忙」开关）。
- **依据：** [`research/physics/REPORT.md`](../../research/physics/REPORT.md) §5（离合入齿）、§5.5（剩下的误差从哪来）、§7（建议）。

## 要求

刚体物理复核（REPORT 结论 6）发现：宋史式每次放下小平轮，大平轮都会被重新对到最近的齿槽，所以车夫再小心，拐弯多了木人也会慢慢偏。网页原来的仿真是纯运动学，离合瞬间完成、没有误差，「车夫帮忙」时木人永远 0°。

老板的选择：「网页也算入齿误差」。统筹定的约束：放下小平轮时按真实齿位对到最近的齿槽；误差确定、不用随机数、单次不超过半齿（3.75°）；开「车夫帮忙」多拐几次弯，木人会慢慢偏几度。差动式不动，也不为测试放宽差动式的标准。

## 怎么算

小平轮抬着的时候，它不转，立子轮却一直跟着车轮转。所以再放下时，它的齿一般对不上立子轮的齿缝，也对不上大平轮的齿缝。物理里谁让步（REPORT §5 开头和 §1「规定运动与自由度」）：

- **车轮**着地，被车推着走，不让；立子轮固定在车轮上，也不让。
- **小平轮**抬着时是自由的，落下时被立子轮的齿拨进齿缝。
- **大平轮**连着木人，只能被小平轮拨动。

网页照这个顺序做两步（`js/sim/chariot.js` 的 `#engage`，在离合由抬起变为放下的那一步、车轮本步转动之前执行）：

1. 小平轮转到最近的立子轮齿缝，最多转半个小平轮齿（15°），不影响木人。相位条件见 `docs/model-contract.md`「Song meshing phase」：右边 `small − 2·foot`、左边 `small + 2·foot` 是 30° 的整数倍。
2. 小平轮再把大平轮连同木人推到最近的齿槽，使 `small + 4·bigFlat` 是 30° 的整数倍。大平轮最多转半个大平轮齿，即 7.5° / 2 = **3.75°**，木人也跟着转这么多。

两步都是取模取最近，只依赖当时各齿轮的转角，**没有随机数**：同一条路线、同一种开法，结果每次都一样。误差只在放下的那一步出现，其余步与运动学完全一致。直行多远都不会产生误差，因为直行时不放下小平轮。

pose 新增两个量：`engagements`（放下过几次）、`engageDeg`（这些放下给木人加了多少度，带符号累加）。

**没算的两项**（物理里有）：

- **整齿跳**：最佳设定下约 4% 的入齿错过整整一个大平轮齿（7.5°），REPORT §5.5。它要靠动力学才说得清是哪一次，确定性模型做不到，就不做。
- **齿隙换边**：每次 ±1.5°，换边时还回来，不累积（REPORT §5.1）。

### 回放改成固定步长

入齿误差取决于**放下那一刻**各齿轮的转角，而回放器原来按帧推进，每帧路程随帧率变：同一条 circle 路线，车夫帮忙时末值在 6°–15° 之间随帧率跳。`js/app/playback.js` 的 `FollowPlayer` 改为按固定的 1/60 路线秒推进（`FOLLOW_TICK`），一帧里补够若干 tick。回放末值从此与帧率、播放快慢无关，课文里写的「最后指着哪儿」才对得上每个孩子的屏幕。

## 网页现在给出的数

宋史式、车夫帮忙，旧版各路线末值全是 0.000°。新版：

| 路线 | 入齿次数 | 末值 |
|---|---|---|
| straight / reverse / spin | 0 | 0° |
| pivotLeft | 2 | 2.0° |
| pivotSquare | 4 | −3.0° |
| pivotZigzag（第 5 课新步） | 3 | −6.0° |
| circle | 55 | 6.3°（途中最大 10.0°） |
| sCurve | 43 | 1.5° |
| figureEight | 80 | 17.0°（途中最大 34.6°） |
| 手绘画线路线 | 130 | 14.7°（途中最大 24.9°） |

不帮忙的普通转弯本来就偏（circle 约 60°），入齿误差叠在上面，看不出区别。差动式没有离合，`engagements` 恒为 0。

HUD 的「偏 N°」、`js/app/checks.js` 的「偏了 5° 算弄偏」、selftest 都不用改：HUD 正好把偏几度显示出来；「弄偏」任务要求车先被弄坏（`broken`），入齿误差不会让好车冒充过关；selftest 只查数值有限。

## 和物理比

物理复核用的是新几何（0006 补的屋脊齿和倒角）、最佳设定（上油 0.1 + 插销），全部 51 条宋史式路线、854 次入齿（结果在 `/tmp/zhinanche-polish/song-error/physics/`，不进版本库；复跑见 REPORT「复现」，几何改读本分支的 `params` 和 `layout.py`）：

- **量级一致，网页略小。** 20 条随机「绕内轮」路线（每条 11–22 次入齿），末值绝对值中位 / 最大：网页 4.7° / 15.3°，物理 7.2° / 24.6°。网页小一些，是因为没算整齿跳和齿隙。
- **单次大小一致。** 逐次配对 854 次入齿：物理每次入齿的跳变，绝对值中位 1.70°、p90 4.37°；网页的修正中位 1.91°、p90 3.32°。
- **单次方向对不上。** 两者的相关系数只有 0.07–0.14。扫过相位偏移、加过死区，都没有提高，最佳偏移约为 0，所以不是相位约定写反了。逐条路线的末值，网页和物理相差中位约 9°。

解释（推断）：「对到最近齿槽」给出的是误差的大小，以及它随入齿次数累积的规律，但预测不了每一次往哪边偏。齿隙有 48%，小平轮落座时，大平轮停在齿隙里的哪个位置不确定；落座过程本身还受动力学影响（物理里约 20% 的入齿要等车开起来才落座）。所以网页说「拐多了会慢慢偏几度」是对的，但不应该说「这条路线真车会偏 −6°」。课文没有这么说。

## 课文怎么讲

读者 9–12 岁，不出公式（`js/teach/lessons.js`、`lessons.en.js` 第 5 课「古人的两种造法」）：

1. 「关掉车夫帮忙绕一圈」那一步之后，加一步：车夫帮忙、拐三个弯（pivotZigzag，末值 −6.0°，3 次入齿），问「车夫帮忙时，木人为什么还会歪一点点？」，答「小平轮落下时，齿要重新对上」。正文讲小平轮抬着时立子轮还在转，落下要挤一挤，把大平轮拨动一点点。
2. 再加一步（齿轮视角、透视、高亮小平轮和大平轮）：真造这种车，要上油、把齿顶削尖一点、用铁坠子或插销压住小平轮；吴德仁的车两个小平轮各挂一个铁坠子（《宋史》卷 149「二小平輪，各有鐵墜子一」）；差动式的齿轮一直咬在一起，不抬不落，没有这个麻烦。

原来说「车夫这样赶车，木人才指得准」的地方改成「指得差不多准」。「车夫帮忙」开关的说明、首页「它会走偏吗」「古人真的这么造吗」两个问答各补一句：拐弯多了会慢慢偏几度。

## 代价

- 宋史式车夫帮忙不再是「完全准」。课文原本用它来对比「关掉就偏」，现在对比的是「偏几度」对「偏几十度」，仍然看得出来。
- 每次放下多两次取模，计算量可以忽略。
- 测试改成逐步断言：只有入齿那一步木人会变，且每次不超过 3.75°；其余步与运动学一致；放下后两对齿都在相位上；`engageDeg` 等于各次之和（`tests/sim/chariot.test.js`）。
- `pnpm check:model` 不再跳过「放下但相位不对」的姿态。原来这类姿态记 WARN（4 对），现在仿真放下时总在相位上，出现失相位就 FAIL。

## 没覆盖什么

- 整齿跳和齿隙换边（见上）；所以网页的误差比物理略小。
- 每次偏哪边：网页是确定的，物理上不可预测（相关系数约 0.1）。
- 离合边走边落：仿真和物理都是停车后瞬间或慢慢放下，原文「推轅右旋」是边推边落，没有建模（REPORT「没覆盖什么」）。
- 吴德仁本的 13 个轮：没有建模。
